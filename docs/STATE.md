## CI — четыре джоба

1. **Миграции и тест изоляции тенантов** — чистая база, миграции с нуля, 30 проверок изоляции, линтер базы

4. **Деплой Edge Functions** — только при пуше в `main`

## Решения по схеме каталога

**Составные внешние ключи `(id, tenant_id)`.** Обычный ключ по одному `id` позволил бы привязать вариант товара одной компании к товару другой. RLS такую запись не поймает: каждая строка по отдельности законна, нарушение только в связи между ними. Составной ключ делает это невозможным на уровне базы. В тесте изоляции есть отдельная проверка.

**SKU уникален внутри тенанта, а не глобально.** У разных продавцов артикулы совпадают, это норма. Проверка в тесте.

**Мягкое удаление через `archived_at`.** Товар фигурирует в старых заказах, физически удалять нельзя.

**`create_product` создаёт товар и первый вариант одной операцией.** Товар без варианта бессмыслен: SKU, себестоимость и остаток живут на варианте. Два отдельных запроса с фронта дали бы товар-сироту при обрыве связи.

**Себестоимость — `numeric`, валюта отдельной колонкой.** `float` теряет копейки на сложении. Деньги во фронте не считаются, только форматируются.

## Технический долг, принятый осознанно

- Бандл одним чанком. Резать по маршрутам при росте.
- Разделы Заказы, Склад, Аналитика, Настройки — заглушки.
- Иконки меню — квадраты-заглушки.
- **Поиск в каталоге только по названию.** Поиск по SKU и штрихкоду требует условия «название ИЛИ артикул» через связь, а PostgREST одним запросом это не выражает. Нужна функция в базе — та же функция потом послужит сканеру штрихкодов на складе.
- **Категории и бренды создаются только напрямую в базе.** Экранов управления справочниками пока нет, в форме товара они выбираются из готового списка.
- Диспетчер очереди не знает про приоритет тенантов.
- Edge Functions едут на прод без staging.
- Задача `heartbeat.ping` остаётся в базе как индикатор здоровья очереди.
