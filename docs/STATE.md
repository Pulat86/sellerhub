## CI — четыре джоба

1. **Миграции и тест изоляции** — чистая база, миграции с нуля, 35 проверок, линтер базы
2. **Сборка фронтенда**
3. **Типы из схемы** — генерация и коммит обратно
4. **Деплой Edge Functions**

**Важное следствие джоба 3.** Новая функция или таблица появляется в типах только после зелёного прогона. Код фронта, вызывающий её, пушится **следующим** коммитом, а не вместе с миграцией. Иначе сборка падает гарантированно.

## Склад — схема готова, экранов нет

Миграции 0015–0016: `warehouses`, `stock_movements`, представление `stock_balances`, функции `transfer_stock`, `stock_report`, `stock_journal`.

### Ключевые решения

**Остаток не хранится числом.** Он вычисляется как сумма движений. Хранимый остаток расходится с реальностью при первом сбое и не отвечает на вопрос «почему их столько».

**Журнал только пополняется.** На `stock_movements` заведены политики только на чтение и вставку — ни для пользователей, ни для сервисной роли нет политик на изменение и удаление. При включённом RLS отсутствие политики означает запрет. Ошибка исправляется обратным движением.

**`security_invoker` на представлении остатков.** Без него представление исполняется от имени владельца и показывает остатки всех компаний. В тесте есть отдельная проверка.

**`on delete restrict` у журнала.** Удалить вариант или склад, по которому было движение, нельзя — вместе с ними исчезла бы история учёта. Для вывода из оборота есть архивация.

**Перемещение — одна функция.** Списание и приход неразделимы. Два запроса с фронта при обрыве связи создали бы товар, ушедший с одного склада и никуда не пришедший.

## Технический долг

- Бандл одним чанком. Резать по маршрутам при росте.
- Разделы Заказы, Аналитика, Настройки — заглушки.
- Иконки меню — квадраты-заглушки.
- Диспетчер очереди не знает про приоритет тенантов.
- Edge Functions едут на прод без staging.
- Задача `heartbeat.ping` остаётся как индикатор здоровья очереди.
- **Отрицательный остаток не запрещён.** Списание большего, чем есть, пройдёт. Сделано намеренно: продажа с площадки может прийти раньше приёмки, и жёсткий запрет заблокировал бы синхронизацию. Пересмотреть после появления заказов: тогда отрицательный остаток должен стать видимым предупреждением на экране.
